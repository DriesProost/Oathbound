# The Living Campaign

The five destinations are Keep, Quests, Journey, Chronicle and Knight. Real-life reward receipts remain the only source of Renown and XP. Fictional scenes and combat never grant, remove or rewrite progression. Existing Eight Great Systems records are retained, with a quieter presentation.

## Presentation

Keep combines the knight summary, a scene, six evolving rooms, their permanent residents and the Relics actually placed there. Enter a room to read its resident’s current remark; Tomas's Songbook is inside the Great Hall. The duplicated Keep deed/Oath dashboard is removed; Quests owns practical actions. Journey is the single step-driven road: current position, next destination, one active story quest and its choices/confrontation. Its closed journal preserves every visited place, story page, choice, battle and the earlier Oakhaven chapter. Restoration and the full itinerary are optional disclosures. Chronicle contains actual campaign history, weight, Venture ledger and factual week/month manuscripts. Titles and Techniques are profile details in Knight.

## Save v6 and truth boundaries

`living/model.ts` adds a versioned `living` object: settings, structured story canon, current battle and archived battles. `storage.ts` validates all legacy data, preserves every existing field, and writes the exact v5 source to `oathbound.knight.v5.living.backup` before committing `oathbound.knight.v6`. The old save and prior migration backups remain untouched. Backup failure prevents commit. A corrupt newer save never falls back to an older one. Migration creates no historical story scenes, choices or fights. Existing world milestones, songs, factual pages, reward snapshots and encounter memories survive unchanged.

New story events use the date they are read or chosen. The director never changes `entries`, `oaths`, `ventures`, `weekly`, `weight`, or `world` rewards. Combat returns a changed `living` object only. Existing factual Oath corrections and retrospective deeds patch only affected factual pages, including later cumulative crossings. Month summaries use the same source facts and correction boundary. Stale AI manuscript arrangements are removed only for affected pages.

## AI: GPT-6 Luna only

`living/aiConfig.ts` is the central production policy: **`gpt-6-luna`, low reasoning, no escalation**. Every runtime request—scene, Venture/lesson, dialogue, Chronicle arrangement or Bard suggestion—uses that model. Settings display the policy rather than offering other models. The provider disregards caller-supplied model substitutions; a backend response identifying another model family is rejected. There is no fallback model. Tests cover both protections.

`NarrativeProvider.generate()` accepts a typed task, a compact derived context, a schema and task instructions. `JsonNarrativeProvider` implements an OpenAI-compatible chat-completions backend with a 12-second timeout, one retry for transient HTTP statuses, bounded output, JSON parsing, omitted credentials/referrer, and no redirects. A frozen Campaign Bible accompanies every call. Separate closed validators reject unsupported state/reward/combat fields before any content is accepted. React renders plain escaped text, never generated HTML.

AI is **off by default**. To enable it, configure an HTTPS chat-completions endpoint supporting CORS and the Luna model (localhost HTTP is allowed for development). A backend should keep its provider credential server-side. A direct API key can be remembered in this browser’s local storage with the visible **Remember key on this device** option, or retained for the open session only. It is stored under a separate credential namespace, never in campaign saves, exports, narrative context, the bundle or logs. It is bound to the exact normalized endpoint, so changing host or path cannot automatically forward the old secret. Blank preference saves keep the existing key; switching retention or **Forget saved key** removes the persistent copy. Browser-stored keys are local storage, not encrypted server-side secrets; use a trusted device or a backend. GitHub Pages supplies no private AI backend and this release includes **no real runtime AI credential**. Live Luna output cannot be verified without that configuration; integration tests intercept a mock endpoint and separately exercise actual browser fetch/JSON handling. Provider outages, unavailable Luna, invalid JSON and rejected content return authored/deterministic content.

Content prepares automatically while the app is visible. A persisted reservation journal and browser lock prevent repeated paid work across renders, reloads and tabs; interrupted jobs recover with authored content. One daily scene is prepared without advancing the story. The player reveals it with **Read the next page**, at most once per local date; unread prepared scenes wait indefinitely across skipped days. Dialogue is daily, manuscript arrangements follow factual source identities, and Bard ideas accompany weekly manuscripts or arc endings. Accepted content has stable cache identities. Async results merge only their unchanged target, preserving concurrent deeds and preferences. No continuous network polling is used.

## Structured continuity and endless arcs

Story state contains current arc identity/title/premise/stage, planned next arc, unresolved hooks, recurring NPCs and relationships, places, choices, mysteries/completed mysteries, fictional world facts, saved beats, future seeds, mood/season/weather and generation provenance. The compact AI packet includes only relevant derived facts and a bounded recent fictional context, not the whole save.

Six connected seven-stage quests follow the route: The Empty Watchtower, The Miller’s Winter Ledger, The Bell That Rings at Noon, The Survey Above the Trees, The Packet with Three Postmarks and The Lantern in Low Cloud. A page has a stable arc/stage ID. At most one new scene is accepted per local day; each pickup/page is unlocked by its centrally authored cumulative walking-distance threshold in `journey.ts`, rather than a count of deeds. Unanswered choices and unsettled confrontations pause their own story thread. No timer, expiry, activity loss or missed-day counter exists. A concluding response can propose a strictly validated next title/premise/mystery. After all six authored quests, subsequent arcs use an open-road structure rather than reopening solved seeded mysteries; their mysteries and choices remain distinct. The authored degraded mode can also continue beyond the seeded arcs. Generated NPCs and places can be added, never overwrite established identities. Combat outcomes and completed generated Venture opportunity hooks enter the next request as structured context. A retreat/defeat produces an alternate fictional route, never invented victory or destroyed progress.

## Generated Ventures

All 60 authored Ventures remain bundled as the daily library and offline fallback. With AI enabled, a fresh first notice can prepare automatically before it is opened; an opened, completed or replaced notice is protected. **Choose another Venture** still uses the same once-per-day replacement path. Attribute rotation, tier weighting, Bold frequency guard, completion and reward snapshots all continue through `ventureDomain.ts`. AI never supplies rewards. Brief/Standard/Bold rewards remain exactly the current centrally configured Renown and XP pools, including split XP for two attributes.

Generated notices have closed fields, bounded text, appropriate duration, tags/equipment, optional reflection/lesson, provenance and a fictional consequence hook. Constraints are checked again against preferred duration, outdoors and available equipment. Wisdom readings require 150–500 words and no scored test. Physical generation is deliberately conservative: the current closed plans are comfortable bodyweight practice, an easy walk and gentle mobility. AI must copy a plan's safe instructions, Brief tier and duration exactly; it cannot prescribe arbitrary workouts. Dangerous exercise/medical/diet instructions are filtered, including physical prescriptions disguised as another attribute. This is a conservative content gate, not a claim that arbitrary language can be proven safe. Add more reviewed physical plans as authored data when desired. Lessons are marked AI-authored; subject accuracy and originality remain model-quality limitations. No live medical advice is requested.

## Tactical combat

Twelve Techniques: Measured Cut, Set the Shield, Catch Breath, Half-Sword, Shield Bind, Scout's Step, Read the Shoulder, Hester's Stand, Second Wind, Tomas's Remark, Close Quarters and Press the Advantage. Discovery comes from permanent residents or the established road; attribute thresholds make learned techniques usable. There is no random equipment treadmill or battle reward farming.

Seven enemies: Road Brigand, Shielded Deserter, Poacher, Wild Boar, Veteran Swordsman, Two Roadside Thieves and Tavern Challenger. Enemy patterns are deterministic arrays of Heavy swing, Quick strike, Guard, Feint, Recover, Grapple and Retreat. The seeded stories include fixed confrontations; later arcs rotate grounded opponents. Appropriate alternatives use deterministic Presence, Wisdom, Endurance or Resolve thresholds. Some practice bouts require combat to settle their own scene, but none blocks ordinary deeds, Ventures or real-life growth.

Health, Stamina, Guard and Momentum use `combatContent.ts` constants and bounded linear scaling. Strength improves damage/Guard breaking; Endurance affects Stamina/recovery; Resolve strengthens Guard; Vitality increases Health/recovery; Wisdom reveals further intent and analysis; Presence enables social alternatives and disruption. Level contributions cap at 20. Retinue and real attribute snapshots, enemy stats/pattern and resources are persisted at battle entry so reload/configuration changes cannot silently reroll the enemy. Each explicit technique consumes one deterministic turn. Battles are capped at 40 turns, logs stay small, and once-per-fight techniques are enforced. Withdrawal or defeat never removes any actual campaign progress. New attempts begin with full resources. A withdrawn mandatory practice bout may be resumed with a new attempt; archived attempts stay recorded. AI can frame a fixed enemy ID but cannot supply enemy stats, actions, rolls, resources or results.

## Artwork, animation and offline operation

`living/assets.ts` is the replaceable art registry for rooms/stages, portraits, road locations, enemies, Relics, arcs and weather. The release reuses existing Keep/mill/inn/village images and adds original SVG forests, fields, monastery/watchtower architecture, room props, residents, named Relic placement and enemy figures (including a boar and two-person group). Final painted portraits, room art, enemy art, weather sheets, arc key art and additional music remain intentional asset slots/placeholders. No downloaded third-party art or new audio playback is introduced. New registry images may be imported centrally; no request-time generated art is needed.

CSS provides candle/hearth warmth, rain, room reveals, manuscript fades, shield/weapon/recoil responses and text-labelled intent/resource changes. Reduced motion disables every new decorative animation. Native buttons/details, text intents/logs, semantic meters, 44px controls and responsive layouts support keyboard, screen readers and small touch screens. No canvas loop, continuous network polling or new runtime dependency is introduced. Existing shell precaching includes all new modules/content. Cached AI content, authored Ventures, factual history, Songbook and deterministic combat work offline; external AI requests are never cached by the service worker.

## API setup and connection test

**Knight → Narrative preferences** fills a blank endpoint with `https://api.openai.com/v1/chat/completions`. Existing custom endpoints are preserved. Paste an existing key once, choose retention and save. Saving without typing a new key preserves the existing credential. This is a device preference, so no campaign/save migration is required.

**Test connection** checks the current form values with one small real chat-completions request: GPT-6 Luna, low reasoning, maximum 512 completion tokens, JSON `{"ok":true}`. It sends no campaign packet and does not enable AI, save a draft key, award progress, add story content, cache a false success or run through authored fallback. It confirms the returned model and JSON and supports cancellation. Changing endpoint/key clears an earlier result. Diagnostics distinguish invalid credentials, model access, permissions, billing/quota, rate limits, missing endpoint, network/CORS, timeouts, malformed JSON and a different/unconfirmed model. Only known safe diagnostic messages are displayed; raw backend error messages can echo secrets and are never surfaced. Test requests are not retried or escalated to another model. Normal narrative requests retain their bounded transient retry and authored fallback behavior.

Verification for the credential/connection patch: 276 tests across 41 files and the repository-base production build passed. `scripts/ai-connection-smoke.cjs` exercises the actual UI with an intercepted endpoint: key survives reload, blank preference saves retain it, another endpoint receives no old key, successful JSON/model verification, redacted authentication/model/quota errors, forgetting/cancellation, unchanged campaign history and responsive layouts. No real private API key was available for a live OpenAI test; the user-facing button performs that check on the configured device.

## Unified step-driven Journey

The route is the adventure’s progression source. The first story quest is picked up at Oakhaven (40,000 estimated route steps); its first confrontation is at Northwatch Tower (60,000 steps), reached as page five after the preceding choice. Step thresholds unlock each page, while the existing one-read-per-local-day cap and choice/confrontation gates preserve sequence. One large patrol unlocks opportunities without silently reading pages, deciding choices or playing combat turns. Ordinary deeds, calendar age, Renown and attribute XP no longer advance this story. Daily Ventures and ordinary deed rewards remain separate and unchanged. Luna prompts use a compact current/next-place and pickup context and request short connected scenes; accepted long scenes remain intact behind an optional full-scene disclosure.

Sixteen authored destinations run from the Keep to Lantern Hill at 750 km (1,000,000 estimated route steps). The first four IDs, distances and full chapters remain unchanged. Twelve new destinations, original short visits and four further seven-scene quests ship offline. The map displays one four-stop region at a time; viewing another region changes neither position nor progress. One current-place card and a specific quest objective show where to look; optional recap and a single closed journal provide rereading without a wall of open chapters.

New household introductions use the same route registry: Tomas at Old Mill (9 km), Ysabel at Wayfarer’s Inn (21), Edric at Oakhaven (30), Oswin at Northwatch (45), Hester at Stonebridge (65), Aldren at Alder Abbey (90), and Elin at Reedmere (120). This deliberately supersedes the earlier level/age fallback arrival rules following the product direction that NPCs come from the walking Journey. Attribute levels still govern Technique use. Existing permanent arrivals remain authoritative; nobody is removed from the Keep after an upgrade or correction.

No new save format or migration is needed: v7 story/choice/battle snapshots, queued unread pages, residents, rewards, history and backups remain intact. A page already prepared under earlier rules stays readable even below the new route threshold. Future pages use the route gates. The new landmark thresholds use the existing single arrival-feedback surface and award no additional Renown or XP. Quiet upgrade/reload never replays arrivals.

New arcs carry optional validated pickup metadata (stable place ID, name and route threshold snapshots). Legacy arcs remain valid without it and are labelled as an ongoing story rather than assigned an invented historical pickup. Authored quest titles/mysteries remain aligned with their route scenes; older accepted arc/beat text is never rewritten. After the authored chain, the existing open-road continuation and provider abstraction remain available.
