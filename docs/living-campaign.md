# The Living Campaign

The five destinations are Keep, Quests, Journey, Chronicle and Knight. Real-life reward receipts remain the only source of Renown and XP. Fictional scenes and combat never grant, remove or rewrite progression. Existing Eight Great Systems records are retained, with a quieter presentation.

## Presentation

Keep combines the knight summary, a scene, six evolving rooms, their permanent residents and the Relics actually placed there. Enter a room to talk; Tomas's Songbook is inside the Great Hall. The duplicated Keep deed/Oath dashboard is removed; Quests owns practical actions. Journey presents the ongoing story and confrontations, with the earlier Oakhaven chapters/encounters tucked into an expandable earlier-road manuscript. Restoration remains road scenery. Chronicle includes actual campaign history, weight, Venture ledger, week/month factual manuscripts and a clearly labelled fictional story archive. Titles and Techniques are profile details in Knight.

## Save v6 and truth boundaries

`living/model.ts` adds a versioned `living` object: settings, structured story canon, current battle and archived battles. `storage.ts` validates all legacy data, preserves every existing field, and writes the exact v5 source to `oathbound.knight.v5.living.backup` before committing `oathbound.knight.v6`. The old save and prior migration backups remain untouched. Backup failure prevents commit. A corrupt newer save never falls back to an older one. Migration creates no historical story scenes, choices or fights. Existing world milestones, songs, factual pages, reward snapshots and encounter memories survive unchanged.

New story events use the date they are read or chosen. The director never changes `entries`, `oaths`, `ventures`, `weekly`, `weight`, or `world` rewards. Combat returns a changed `living` object only. Existing factual Oath corrections and retrospective deeds patch only affected factual pages, including later cumulative crossings. Month summaries use the same source facts and correction boundary. Stale AI manuscript arrangements are removed only for affected pages.

## AI: GPT-6 Luna only

`living/aiConfig.ts` is the central production policy: **`gpt-6-luna`, low reasoning, no escalation**. Every runtime request—scene, Venture/lesson, dialogue, Chronicle arrangement or Bard suggestion—uses that model. Settings display the policy rather than offering other models. The provider disregards caller-supplied model substitutions; a backend response identifying another model family is rejected. There is no fallback model. Tests cover both protections.

`NarrativeProvider.generate()` accepts a typed task, a compact derived context, a schema and task instructions. `JsonNarrativeProvider` implements an OpenAI-compatible chat-completions backend with a 12-second timeout, one retry for transient HTTP statuses, bounded output, JSON parsing, omitted credentials/referrer, and no redirects. A frozen Campaign Bible accompanies every call. Separate closed validators reject unsupported state/reward/combat fields before any content is accepted. React renders plain escaped text, never generated HTML.

AI is **off by default**. To enable it, configure an HTTPS chat-completions endpoint supporting CORS and the Luna model (localhost HTTP is allowed for development). A backend should keep its provider credential server-side. A direct API key can be supplied for the current open session only; it is never placed in saves, localStorage, the bundle or logs. GitHub Pages supplies no private AI backend and this release includes **no real runtime AI credential**. Live Luna output cannot be verified without that configuration; integration tests intercept a mock endpoint and separately exercise actual browser fetch/JSON handling. Provider outages, unavailable Luna, invalid JSON and rejected content return authored/deterministic content.

No request occurs on render, reload or a polling timer. Generation happens when a player explicitly asks for a page, replacement notice, remark, arrangement or song idea. Accepted scenes are permanent snapshots; daily dialogue/verses, daily assignments and factual arrangements have stable cache identities. Async UI operations reject stale results after another state change or date rollover.

## Structured continuity and endless arcs

Story state contains current arc identity/title/premise/stage, planned next arc, unresolved hooks, recurring NPCs and relationships, places, choices, mysteries/completed mysteries, fictional world facts, saved beats, future seeds, mood/season/weather and generation provenance. The compact AI packet includes only relevant derived facts and a bounded recent fictional context, not the whole save.

`The Empty Watchtower` and `The Miller's Winter Ledger` provide complete seven-stage structures. A page has a stable arc/stage ID. At most one new scene is accepted per local day; later pages need two further real-life actions. Unanswered choices and unsettled confrontations pause their own story thread. No timer, expiry, activity loss or missed-day counter exists. A concluding response can propose a strictly validated next title/premise/mystery. Subsequent arcs use an open-road structure rather than reopening solved seeded mysteries; their mysteries and choices remain distinct. The authored degraded mode can also continue beyond the seeded arcs. Generated NPCs and places can be added, never overwrite established identities. Combat outcomes and completed generated Venture opportunity hooks enter the next request as structured context. A retreat/defeat produces an alternate fictional route, never invented victory or destroyed progress.

## Generated Ventures

All 60 authored Ventures remain bundled and are the default daily library and offline fallback. With AI Ventures enabled, **Choose another Venture** asks Luna for the day's replacement, using the same once-per-day replacement path. This intentionally does not silently replace a notice the player has already seen. Attribute rotation, tier weighting, Bold frequency guard, completion and reward snapshots all continue through `ventureDomain.ts`. AI never supplies rewards. Brief/Standard/Bold rewards remain exactly the current centrally configured Renown and XP pools, including split XP for two attributes.

Generated notices have closed fields, bounded text, appropriate duration, tags/equipment, optional reflection/lesson, provenance and a fictional consequence hook. Constraints are checked again against preferred duration, outdoors and available equipment. Wisdom readings require 150–500 words and no scored test. Physical generation is deliberately conservative: the current closed plans are comfortable bodyweight practice, an easy walk and gentle mobility. AI must copy a plan's safe instructions, Brief tier and duration exactly; it cannot prescribe arbitrary workouts. Dangerous exercise/medical/diet instructions are filtered, including physical prescriptions disguised as another attribute. This is a conservative content gate, not a claim that arbitrary language can be proven safe. Add more reviewed physical plans as authored data when desired. Lessons are marked AI-authored; subject accuracy and originality remain model-quality limitations. No live medical advice is requested.

## Tactical combat

Twelve Techniques: Measured Cut, Set the Shield, Catch Breath, Half-Sword, Shield Bind, Scout's Step, Read the Shoulder, Hester's Stand, Second Wind, Tomas's Remark, Close Quarters and Press the Advantage. Discovery comes from permanent residents or the established road; attribute thresholds make learned techniques usable. There is no random equipment treadmill or battle reward farming.

Seven enemies: Road Brigand, Shielded Deserter, Poacher, Wild Boar, Veteran Swordsman, Two Roadside Thieves and Tavern Challenger. Enemy patterns are deterministic arrays of Heavy swing, Quick strike, Guard, Feint, Recover, Grapple and Retreat. The seeded stories include fixed confrontations; later arcs rotate grounded opponents. Appropriate alternatives use deterministic Presence, Wisdom, Endurance or Resolve thresholds. Some practice bouts require combat to settle their own scene, but none blocks ordinary deeds, Ventures or real-life growth.

Health, Stamina, Guard and Momentum use `combatContent.ts` constants and bounded linear scaling. Strength improves damage/Guard breaking; Endurance affects Stamina/recovery; Resolve strengthens Guard; Vitality increases Health/recovery; Wisdom reveals further intent and analysis; Presence enables social alternatives and disruption. Level contributions cap at 20. Retinue and real attribute snapshots, enemy stats/pattern and resources are persisted at battle entry so reload/configuration changes cannot silently reroll the enemy. Each explicit technique consumes one deterministic turn. Battles are capped at 40 turns, logs stay small, and once-per-fight techniques are enforced. Withdrawal or defeat never removes any actual campaign progress. New attempts begin with full resources. A withdrawn mandatory practice bout may be resumed with a new attempt; archived attempts stay recorded. AI can frame a fixed enemy ID but cannot supply enemy stats, actions, rolls, resources or results.

## Artwork, animation and offline operation

`living/assets.ts` is the replaceable art registry for rooms/stages, portraits, road locations, enemies, Relics, arcs and weather. The release reuses existing Keep/mill/inn/village images and adds original SVG forests, fields, monastery/watchtower architecture, room props, residents, named Relic placement and enemy figures (including a boar and two-person group). Final painted portraits, room art, enemy art, weather sheets, arc key art and additional music remain intentional asset slots/placeholders. No downloaded third-party art or new audio playback is introduced. New registry images may be imported centrally; no request-time generated art is needed.

CSS provides candle/hearth warmth, rain, room reveals, manuscript fades, shield/weapon/recoil responses and text-labelled intent/resource changes. Reduced motion disables every new decorative animation. Native buttons/details, text intents/logs, semantic meters, 44px controls and responsive layouts support keyboard, screen readers and small touch screens. No canvas loop, continuous network polling or new runtime dependency is introduced. Existing shell precaching includes all new modules/content. Cached AI content, authored Ventures, factual history, Songbook and deterministic combat work offline; external AI requests are never cached by the service worker.
